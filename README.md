# 움짤 메이커

동영상을 잘라 GIF / 동영상 움짤로 만드는 단일 HTML 앱.
**업로드가 없습니다.** 파일은 브라우저 밖으로 나가지 않고, 프레임 추출부터 GIF 인코딩까지 전부 기기 안에서 처리됩니다.

👉 **https://rabit0219.github.io/gifmaker-local/**

## 기능

- **모드** — 일반 / 부메랑 (프레임 왕복 재생)
- **크롭** — 드래그 가능한 크롭 박스 (8방향 핸들, 삼분할 그리드), 비율 프리셋 `자유 / 1:1 / 4:5 / 9:16 / 16:9 / 3:4`
- **배속** — 0.25 / 0.5 / 1.0 / 1.5 / 2.0 / 3.0 / 5.0x
- **구간 자르기** — 듀얼 슬라이더로 시작·끝 지정. 프레임 장수에 실질적 제한이 없습니다 (수백~천 장, 추출 중 취소 가능)
- **출력** — 애니메이션 WebP (화질 60~95%, **아이폰 포함 모든 브라우저**) / GIF (팔레트 64·128·256색, Floyd–Steinberg · Bayer 디더링) / MP4·WebM
- 저장한 포맷들의 용량이 나란히 표시되어 바로 비교할 수 있습니다
- **저장 방법을 고를 수 있습니다** — `앨범에 저장 · 공유` / `파일로 저장` / `위치 선택해 저장`
- 설정은 브라우저에 기억됩니다

## 쓰는 법

1. 위 링크를 열고 동영상을 선택 (폰이면 사진앨범에서 바로 고를 수 있습니다)
2. 슬라이더로 구간을 자르고, 필요하면 크롭·배속·모드를 설정
3. **움짤 만들기** → 미리보기 확인 → **WebP / GIF / 동영상** 중 하나로 인코딩
4. 인코딩이 끝나면 저장 방법을 고릅니다 — 폰이면 **앨범에 저장 · 공유**를 눌러
   공유 시트에서 `[이미지 저장]` / `[비디오 저장]`을 선택하면 앨범에 들어갑니다

### 저장 방법

| 버튼 | 동작 | 나오는 환경 |
|---|---|---|
| 앨범에 저장 · 공유 | `navigator.share({files})` → 네이티브 공유 시트 | 폰(iOS·Android), 일부 데스크톱 |
| 파일로 저장 | `<a download>` 로 바로 내려받기 | 항상 |
| 위치 선택해 저장 | `showSaveFilePicker()` 로 폴더 지정 | Chrome·Edge 데스크톱 |

공유 시트를 못 쓰는 환경에서는 인코딩이 끝나는 즉시 바로 내려받습니다(예전 동작 그대로).
iOS 는 `<a download>` 가 파일을 저장하지 않고 새 탭에서 열어버려서, 앨범에 넣으려면 공유 시트를 써야 합니다.
GIF·동영상은 공유 시트에 `[이미지 저장]`/`[비디오 저장]` 이 확실히 뜨고,
WebP 는 iOS 사진 앱이 받아주지 않아 `[파일에 저장]` 만 나올 수 있습니다.

## 어떤 포맷으로 저장할까

| 포맷 | 실측 (240×240, 68프레임 부메랑) | 쓰는 곳 |
|---|---|---|
| **WebP** | **22KB** | 기본 추천. 이미지라서 GIF처럼 `<img>`·문서에 그대로 붙고, 최신 브라우저 전부 재생 |
| MP4 | 25KB | 움직임이 많고 긴 영상. 인터프레임 압축이 있어 그럴 때 유리 |
| GIF | 155KB | 카톡·구형 커뮤니티처럼 GIF만 받는 곳 |

같은 움짤에서 WebP가 GIF의 **1/7** 입니다 (정적 배경이 많으면 1/10까지). 세 포맷 다 저장해 보면
결과 카드에 용량이 나란히 떠서 바로 비교됩니다. 그래도 크면 `가로 크기` → `초당 프레임` 순으로 낮춰 보세요.

## 구현 메모

- 프레임 추출: `<video>` seek + `drawImage` (크롭은 source rect로 처리)
- **프레임은 raw RGBA 로 들고 있지 않습니다.** 추출 즉시 압축 스틸(WebP, 없으면 JPEG q0.94)로
  바꿔 두고 픽셀이 필요한 순간에만 디코딩합니다(비트맵 LRU 캐시). 480×854 기준 raw 는 장당 1.6MB 라
  모바일에서 42장에 막혔지만, 압축 저장은 장당 수십 KB 라 같은 예산에 20배 이상 들어갑니다.
  장수 상한 대신 **누적 저장 용량**을 예산으로 쓰기 때문에 실제로 담기는 만큼 담습니다
  (실측: 291장 요청 → 전량 추출, 누적 86KB. raw 였다면 89MB)
- 중복 프레임 판정은 raw 픽셀을 다시 읽지 않고 **인코딩된 바이트를 비교**합니다
  (픽셀이 같으면 인코더 출력도 바이트까지 같음)
- **애니메이션 WebP는 브라우저에 인코더가 없어서 직접 먹싱합니다.** 프레임마다
  정지 WebP 를 만들고, 그 안의 VP8 비트스트림 청크를 꺼내
  `RIFF`/`VP8X`(애니메이션 플래그)/`ANIM`/`ANMF` 컨테이너로 이어 붙입니다.
- 정지 WebP 는 `canvas.toBlob('image/webp')` 로 만들지만, **Safari 계열은 WebP 를 재생만 하고
  인코딩은 못 합니다.** 그래서 libwebp 를 wasm 으로 파일에 내장해 그런 브라우저에서는 그쪽으로
  돌립니다 (아이폰에서도 WebP 저장이 됩니다). ESM 글루를 클래식 스크립트로 쓰려고 두 군데만
  고쳤습니다 — `import.meta.url` → 변수, `export default` → 전역 팩토리. wasm 바이트는 base64 로
  내장해 `wasmBinary` 로 직접 넘기므로 네트워크 요청이 없고, 인스턴스화는 첫 저장까지 미룹니다.
  libwebp `method` 는 480×854 실측으로 2 를 골랐습니다 —
  m2 21ms/26KB vs m3 63ms/24KB (3배 느린데 8%만 작음)
  프레임마다 이전 프레임과 달라진 영역(dirty rect, ANMF 제약에 맞춰 x·y 짝수 정렬)만 인코딩하고
  `B=1`(덮어쓰기) `D=0`(유지) 으로 합성하므로, 배경이 정적이면 픽셀의 80~90%를 아예 담지 않습니다.
  프레임이 압축 저장이라 정지 영역도 ±1~2 흔들려서, dirty rect 비교에 허용 오차(±3)를 둡니다
- GIF 인코딩: [gifenc](https://github.com/mattdesl/gifenc) 1.0.3 (MIT) 를 파일 안에 인라인 번들로 포함 — CDN·오프라인 걱정 없음
- 팔레트는 전체 프레임을 샘플링해 **글로벌 팔레트 1개**만 사용 (프레임별 로컬 컬러테이블 없음 → 용량 절감)
- Floyd–Steinberg 디더링은 rgb565 캐시로 자체 구현
- 동영상 출력: canvas `captureStream` + `MediaRecorder`
- **느린 배속(0.25x·0.5x)은 프레임을 복제하지 않습니다.** 인접한 동일 프레임을 하나로 합치고
  그 프레임의 표시 시간을 늘립니다. 0.25x 실측 — 288장 샘플 → 49장 유지, 재생 시간은 그대로, GIF 404KB
  (복제 방식이면 같은 결과가 약 2.4MB)

## 브라우저

Chrome / Edge / Firefox / Safari (iOS 포함). 세 포맷 모두 어느 브라우저에서든 저장됩니다.
결과 카드 아래에 그 브라우저의 지원 현황이 표시되고, 안 되는 게 있으면 이유와 대안을 알려줍니다.
iOS는 저장 시 파일이 새 탭에서 열릴 수 있어 길게 눌러 [사진에 추가]하면 됩니다.

## 파일

`index.html` 하나가 전부입니다. 받아서 더블클릭해도, 인터넷이 없어도 그대로 돌아갑니다.

파일이 약 480KB(gzip 185KB)인데 대부분이 내장 libwebp wasm 입니다. CDN 링크나 별도 파일로
빼면 index.html 은 78KB 로 줄지만, 그러면 오프라인·더블클릭 실행이 깨지고 파일을 둘로 관리해야 합니다.
아이폰이 주 사용 환경이라 어차피 그 바이트를 받아야 해서, 한 파일로 두는 쪽을 택했습니다.
